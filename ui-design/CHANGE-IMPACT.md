## Reading the report

Each row identifies the workstream, affected record, reason, responsible person or unallocated follow-up, next step, and an inspection link. Expand retained/current context to inspect exact snapshots. Status filters help separate four conditions:

- **Blocked:** an existing source or package gate prevents continuation. This does not erase prior decisions or execution.
- **Review needed:** current scope applicability or exact receipt is missing/non-applicable. Missing evidence does not establish that a change happened.
- **Historical:** workshop source changed after simulated execution or closure. Retained evidence concerns its original cycle and cannot transfer to the new brief.
- **Current:** no source/scope concern detected for this row. This does not mean authorized, ready, executed, successful or complete; other operational gates still apply.

Counts describe represented records, not distinct root causes, assignments or organizational health. One changed guide may create several related rows. No recorded dependencies means no invented downstream effect; absent records are not counted as healthy.

## Covered relationships

The report derives from the same model functions used by operational screens:

1. Current assessed contribution versus the retained bounded-use source, including preservation of earlier outcome/goal-follow-up decisions.
2. Pending publication/review/authorization handoff package versus current material and controls. A package may change while material still matches; acceptance of the old package remains blocked.
3. Adopted K-01 scope, audience and exact applicability for represented input, delivery, assessment, bounded use and reader evidence.
4. K-01 guide handoff, receipt and applicability for K-02 preparation.
5. Latest workshop brief, exact receipt and any linked guide/applicability decision.
6. Proposed/approved workshop-brief case resolution versus current evidence.
7. Active workshop cycle’s allocation source versus current brief/case resolution, distinguishing pre-execution blocking from retained post-execution/closed history.

Inspect upstream guide/applicability first, then the brief and case, then workshop allocation/preparation. No downstream review, authorization or result is automatically replaced. A stopped use flow with no allocated source-repair responsibility says **Follow-up unallocated** rather than inventing an owner.

Inspection preserves persona and contextual return; guide inspection opens the K-02 shared input view, which provides explicit links to the responsible actor’s work. The report itself cannot switch actors or allocate work. Returning may reset the status filter; it always derives again from current state.

## Continuity and boundaries

No new mutable workspace slice or checkpoint version is introduced. Existing v12 checkpoints restore the underlying records, and the report derives the same effects again. Contribution-only replacement also changes the report through the existing source guards. Inspection/filtering does not write a checkpoint.

This is a bounded Knowledge sample, not a generic dependency engine, backend change feed, predictive impact simulation or complete historical-change audit. Existing authority controls, missing prerequisites and worker capacity still have their own screens. Main SF records and other organizations remain separate. No real publication or workshop outcome is verified here.

Validation covers an upstream revision propagating through all five dependent paths, source/package independence, adopted-scope changes, historical post-execution evidence, missing records, standalone briefs, immutable inspection and checkpoint equivalence. Phone/desktop checks cover status filters, exact snapshots, source navigation, contextual return and narrow-screen overflow.

# Guided organization journey

Iteration 156 provides eight navigable Knowledge snapshots: purpose, allocation, preparation, failure, recovery, exception closure, observations and independent criterion review.

`data/organizationJourney.ts` constructs each snapshot through the existing contribution, exchange, brief, case, workshop and exception transition models. Earlier records remain in later chapters. Checkpoint round-trip tests validate all stages against current replay guards. `journeyChapters.ts` keeps route identifiers independent of the larger generator.

The viewer projects each snapshot through the same brief, goal and workshop scenario models as the working UI. Shared goal summaries, personal next steps and parallel workstream lanes use the chapter's records. Source inspection stays inside the viewer and exposes retained chapter context. It does not navigate into mutable forms or identify a single event as sufficient evidence for an entire workstream.

Chapter URLs support reload and browser history. Navigation and participant preview do not replace, save or mutate the current workspace. Operational and recovery panels are hidden in the viewer. Optional checkpoint export produces an explicitly downloadable synthetic snapshot; applying it requires the existing reviewed workspace import flow.

The story distinguishes failed execution, later successful execution, remedy submission, independent exception closure, observation submission and independent criterion review. A positive K-02 result does not imply all organization goals are achieved. Actor controls are local persona previews; no production authorization, backend connection or real-world result is claimed.

See [presenter walkthrough](WALKTHROUGH.md). Browser checks cover narrow/wide navigation, history, reload, source focus, preserved workspace and export. Model checks cover replay validity and retained failure/remedy/review history.

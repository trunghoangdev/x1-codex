# K-02 workshop delivery · iteration 146

The Knowledge sample now has a separate local operational loop for its member learning workshop. Organization is the shared view; My Work shows the next responsible actor. Open **K-02 → Open workshop delivery**, or `/organizations/knowledge/workshop/K-02?persona=leo`.

## Run the loop

1. Leo delivers the latest workshop brief; Maya records its exact receipt.
2. In the separate workshop-brief coordination case, Leo accepts follow-up and proposes resolution; Maya approves the current source.
3. In workshop delivery, select **Demo organization owner → Offer facilitation**. Review and confirm. An offer creates no assignment or binding.
4. Select **Leo → Accept facilitation** (or decline). Acceptance adds a local Facilitator binding scoped only to K-02 and projects K-02-F into Leo’s work. It does not establish availability, capability or production permission.
5. Leo submits preparation describing audience, practical exercise, the guide-application criterion and constraints. Maya records readiness or requests changes. Changes require another submitted plan and independent readiness review.
6. Leo records a simulated session result. Success still requires a separate observations record before outcome review. Failure permits only insufficient-evidence or criterion-not-met conclusions.
7. Maya assesses the criterion from the exact preparation, execution and observations: met in simulation, insufficient evidence, or not met. None establishes a real participant outcome.

Each step requires text, an exact preview and confirmation. Actor selection is a local demo control, not authentication. The UI provides readable retained brief, latest plan, execution and observations, plus complete frozen records in history.

## Source and continuity

An allocation freezes the latest received brief and its approved case-resolution identity. Before execution, changed brief/guide input or reopened case blocks acceptance, preparation and execution; the owner can cancel, resolve the changed source and offer a new cycle. After simulated execution, observations and assessment may finish against that historical source, explicitly labelled; nothing transfers to a new brief.

Decline, cancellation and outcome review close a cycle. A new cycle needs a fresh offer, acceptance, preparation and readiness review. Completed cycles create no pending response. Accepted completed facilitation remains visible as scoped responsibility history; cancellation removes the effective local binding. Authored sample definitions are not mutated.

Organization, attention, K-02 workstream/workflow/outcome and personal progress share the same state. Workflow and assignment projections reflect the local cycle. Timeline has a **Workshop delivery** filter with exact source records.

Whole-workspace checkpoint **v12** preserves workshop events alongside the existing slices; v1–v11 remain readable. Import replays every transition and validates actor, chronology, frozen brief/case context, sequential identity and source links. Contribution-only import retains workshop history and reports resulting source status. Recovery is explicit, not automatic.

History is bounded to 40 workshop records, with the existing 4 MB checkpoint limit. Full frozen contexts can reach that file limit before the record count. Export/save errors are visible. No shared backend, actual session scheduling, invitations, worker runtime or real participant collection is implemented.

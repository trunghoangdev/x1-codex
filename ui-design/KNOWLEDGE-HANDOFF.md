# Exact input and bounded authority handoff

K-01-H supports owner-proposed contribution handoffs between Leo and a **Demo delegate**, a local principal separate from authored workers and Maya’s editor role. Start with an accepted local responsibility offer. Handoffs are available for current undelivered preparation, including later requested revisions; unresolved commands must be resolved first. A proposal alone leaves the original contributor responsible.

The owner specifies remaining work and a rationale, then reviews the complete package before confirming. Each package freezes:

- Exact input identifier `input-access-brief-v1` and its full content.
- Current draft version, text, note and citation, plus the preceding revision request when present.
- Remaining work, original and proposed contributors, proposer, time and rationale.
- Coordinator contribution rights: prepare/revise K-01-H and submit it to Maya.
- Explicit exclusions: assess one’s own contribution, authorize publication, or inherit an earlier use authorization.

The recipient inspects the input, frozen preparation, remaining work and rights. Acceptance requires three explicit acknowledgements, a rationale, review and confirmation. Only acceptance changes the effective contributor. Decline or owner cancellation preserves ownership and package history. A changed preparation or a new command makes a pending package stale; acceptance is blocked, and the owner can cancel and propose a new package. Only one package can be pending, with up to twenty packages retained in this local exercise.

After acceptance, the current contributor can edit and submit. The former contributor’s preparation view becomes read-only, and K-01-H leaves Leo’s current assignment queue when delegated. The delegate’s separate local My Work exposes the handoff and contribution entrance without adding authored worker membership or role counts. Shared attention identifies the pending recipient or owner of a stale package. Accepted handoffs are not permission provisioning, verified input access, capacity confirmation, editorial assessment or publication approval.

New commands and deliveries record their contributor. Earlier versions retain their original records and authors. Transfers can return responsibility to Leo without rewriting history; Maya still receives and assesses separately. Existing bounded-use source identities and publication decisions remain exact to their original delivery and assessment.

Contribution and whole Knowledge checkpoints use v5 when handoffs are represented and retain earlier format reads. Validators check package scope, immutable input/authority, actor transitions, response acknowledgements, command ordering and performer/delivery links. Historical preparation may differ from later edits; a pending stale package remains valid recoverable history but cannot be accepted. Replacement previews explain that legacy imports can remove handoff history and restore an earlier effective contributor. Recovery stays explicit.

Validation covers transfer and return, stale work, decline/cancellation, unresolved command blocking, malformed scope/authority/performer records, separate use mandates and phone/desktop recipient acceptance and recovery. These are local demo records; no backend or participant result is claimed.

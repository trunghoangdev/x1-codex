# One explicit subsequent bounded-use cycle

Knowledge's local use exercise supports **cycle 2 for the same exact suitably assessed draft-02**. This is a bounded continuation of use conditions and execution, not general contribution versioning or an automatic retry.

## Supported entry conditions

The demo organization owner can plan cycle 2 after cycle 1's publication assessment requests revision to use conditions, use authorization refuses, or outcome review concludes insufficient evidence/criterion not met. Failed execution must receive its separate outcome review first. A positive outcome, a pending first cycle or changed/missing assessed source does not offer continuation. Cycle 2 is the final supported cycle.

For a publication revision/refusal, describe changed audience/use conditions and why the same assessed material remains appropriate. If actual content must change, follow the separate revision, delivery, receipt and assessment path, then allocate a fresh material mandate. See [fresh material use](MATERIAL-USE-REVISIONS.md).

Cycle 2 requires its own publication assessment and authorization. New assessment, authorization, execution, reader observation and outcome IDs have `-cycle-2` suffixes. Earlier authorization does not authorize the next attempt; execution and reader evidence are not copied. Existing guarded use operations still require exact source identity.

The shared progress/attention and personal local inbox now expose the owner's continuation-planning responsibility when eligible. After mandate creation they return to Sam's fresh assessment, then the existing authorization/execution/evidence/outcome sequence. This is a simulated responsibility, not authenticated allocation or worker dispatch.

No external action occurs. Retry scheduling, additional cycles, revocation, live worker execution and server authority remain outside this slice.

# Current virtual organization demo

Updated 2026-10-07 · iteration 109. This presenter guide follows the current UI. For unprompted participant research use the separate [participant tasks](INTEGRATED-PARTICIPANT-WALKTHROUGH.md).

## Start and explain the boundary

Run Vite as described in README, open Demos and select **Start organization demo**. This selects Knowledge Operations and Leo without resetting work. Use a fresh browser profile for an empty demonstration. Persona switching is local preview, not login; all Knowledge work is fictional.

## 1. See the organization

The shared purpose leads into attention, concrete coordination needs and parallel workstreams. Explain the roles, known responsibility and missing follow-up ownership. Authored context and local observations have distinct source labels. Contribution history and policy/agreement details are collapsed; the policy shortcut reveals its heading.

[Desktop overview](previews/109-organization-desktop.png) · [Phone overview](previews/109-organization-phone.png)

## 2. Enter Leo's work

Select **My Work** while Leo is the sample persona. Open **Open contribution · K-01-H**. Read the current task and supplied brief. Enter contribution text and a delivery note, then check the input citation. For example: “Contact the onboarding contact with your cohort, account and access question.”

**Review delivery** shows the exact version; **Record local delivery** freezes it. Delivery does not create receiver receipt. Return to Organization to inspect the local attention signal pointing to Maya.

[Contribution preparation](previews/109-contribution.png)

## 3. Receive and request a revision

Switch **Sample persona** to Maya; use her My Work. Inspect the exact delivered revision. **Record sample receipt · draft-01**, then **Request sample revision · draft-01**. The request is authored scenario guidance, not an evaluation of entered text.

[Maya receiver](previews/109-receiver.png)

## 4. Continue the same work

Switch to Leo, open his contribution and choose **Prepare draft-02**. Update the text, explain the response to the assessment and cite the input again. Review/deliver the revision. Maya can receive draft-02; reassessment remains pending. The earlier version stays inspectable. No publication or verified outcome is established.

Return to Organization. Receipt/revision needs follow local records; authored workstream counters and outcome gaps do not automatically advance. Open **Contribution exchange history · K-01-H** to inspect exact delivery/receipt/assessment links.

## 5. Preserve the session

The save-status line distinguishes current work from the browser checkpoint. Expand **Save or restore Knowledge contribution** and explicitly save. Reload starts empty; review the saved checkpoint before confirming restoration.

To move machines, expand **Move contribution between machines**, export current work, transfer the JSON and import it in a compatible UI version. Preview/confirm replaces current Knowledge work; save explicitly on the destination. See [recovery instructions](CONTRIBUTION-RECOVERY.md).

Optional failure exercise: use **Command delivery simulation → Acknowledgement unknown** before submitting a fresh contribution. Inspect the locked command, then query simulated admission and refresh projection separately. Do not describe this as a real network/server request.

## 6. Inspect software evidence as a separate domain

Select the main software sample. Open My Work → A-1042 for Attempts, Candidate, Checks, Evidence and assessment. Release authority for A-1041 is a separate subject. [Software evidence preview](previews/109-software-evidence.png) · [Detailed software review guide](SF-REVIEW-WALKTHROUGH.md).

Knowledge contributions do not become software candidates or SF runs. Demos → **Inspect retained SF run** supplies a separate real historical redacted metadata example; **Open SF snapshot** supplies a synthetic one. Neither is live. Missing assessment, authority, policy and effect facts remain unavailable.

## End with the product question

Ask whether participants can find their responsibility, understand what another role must do next, and distinguish recorded work from accepted results or actual effects. The prototype demonstrates the experience; actual participant feedback and live backend integration remain outstanding.

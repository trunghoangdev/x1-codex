# Worker capability and declared availability

Two independently authored main-scenario planning profiles illustrate different scheduling needs:

- Jamie: relevant human implementation/review capability; availability unknown because no declaration is supplied.
- Codex: bounded code/check capability conditional on granted tools and repository access; historical coordinator declaration has an explicitly expired reporting window. Current availability remains unknown.

Profiles identify provenance, constraints and declaration timestamps where supplied. They are not validated assessments or live capacity telemetry. Role bindings, assignment counts and proposal acceptance do not determine capability, free time or permission. No utilization percentage, cost or automatic allocation is introduced.

Worker details show profiles (or missing-profile context). Existing responsibility proposals expose candidate profiles through an expandable inspection panel; switching candidates preserves the draft reason and existing allocation workflow. Candidate inspection requires no new navigation, preventing proposal draft loss. Profiles are scoped to the main sample; Knowledge and larger organizations do not inherit them.

The first slice is read-only. Human willingness/schedule and AI tool/environment/run budget need current explicit confirmation. Deterministic executor applicability still needs a subject, environment and execution policy; no executor profile is fabricated here.
